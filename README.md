# 제9세계 캐릭터 아틀라스

누메네라 캐릭터를 생성하고 플레이 기록을 관리하는 비공식 팬 제작 웹 앱입니다.
현재 버전은 룰북 콘텐츠를 포함하지 않는 로컬 저장형 MVP입니다.

## 실행

요구 사항: Node.js 20.9 이상

```powershell
npm install
npm run dev
```

브라우저에서 `http://localhost:3000`을 엽니다.

## 구현된 기능

- Discovery 또는 Discovery + Destiny 룰북 기준을 캐릭터별로 기록
- 타입, 디스크립터, 포커스 및 능력치를 직접 입력하는 캐릭터 생성
- 유형·수식어·특징의 한국어판 명칭과 캐릭터 정체성 문장
- 힘·속력·지성 역량의 현재치, 최대치, 재능 관리
- 기능 등급(무능·비숙련·익숙함·능숙함), 유형별 에소테리·전투술·재간 명칭
- 능력의 비용·사용 조건·사용 여부 기록
- 급용·절차 사이퍼의 종류와 휴대 한도 기록
- 공격 보정·피해, 방어구 수치·힘/속력 비용 기록
- 회복 기회 체크 및 굴림 보너스·결과 기록
- 등급별 성장 선택(각 4 XP, 4개 선택 후 승급) 기록 및 적용
- 장비·사이퍼·아티팩트·신기품 추가·수정·삭제 및 사용 상태 관리
- 쉰, 부상 트랙, 세부 배경 및 관계 기록
- 로컬 초상화 업로드 (2MB 이하)
- LocalStorage 자동 저장, 여러 캐릭터 관리, 복제 및 삭제
- 캐릭터별/전체 JSON 내보내기와 JSON 가져오기 검증
- Google Apps Script를 통한 Google Sheets 서버 저장·불러오기
- 라이트/다크 테마, 반응형 화면, 인쇄 및 PDF 저장 레이아웃

## Google Sheets 서버 연동 설정

연동 경로는 **웹페이지 → Next.js 서버 API → Apps Script → Google Sheets**입니다. Apps Script 인증 비밀값은 서버에만 보관하며, 사이트에서 별도 비밀번호를 입력하지 않습니다. 캐릭터 동기화는 수동으로 실행합니다. 저장은 기존 시트 데이터를 유지하면서 이름이 같은 캐릭터만 갱신하고, 새 이름은 추가합니다.

1. Google Sheets에서 저장용 스프레드시트를 만듭니다.
2. `apps-script/Code.gs` 내용을 [script.google.com](https://script.google.com)에서 새 프로젝트의 `Code.gs`에 붙여넣습니다.
3. Apps Script의 **프로젝트 설정 → 스크립트 속성**에 `SPREADSHEET_ID`(스프레드시트 URL의 `/d/`와 `/edit` 사이 값)와 `SHARED_SECRET`(긴 임의 문자열)을 추가합니다.
4. 코드 편집기 상단의 함수 선택 메뉴에서 `authorizeSpreadsheetAccess`를 선택하고 **실행**을 누릅니다. 본인 계정을 선택하고, 직접 만든 이 스크립트가 스프레드시트에 접근하는 권한을 검토한 뒤 허용합니다. 승인한 후에는 이 함수를 다시 실행할 필요가 없습니다.
5. **배포 → 새 배포 → 웹 앱**에서 실행 계정은 본인, 액세스 권한은 **모든 사용자**로 배포합니다. Apps Script는 소유자 권한으로 실행되며 비밀값을 검증한 요청만 처리합니다.
6. 프로젝트 루트의 `.env.local` 파일에 아래 환경 변수를 설정합니다.

   ```dotenv
   GOOGLE_APPS_SCRIPT_URL=https://script.google.com/macros/s/배포_ID/exec
   GOOGLE_APPS_SCRIPT_SECRET=위에서_설정한_SHARED_SECRET
   SITE_ACCESS_PASSWORD=직접_정한_긴_사이트_비밀번호
   ```

7. 개발 서버를 다시 시작합니다. 사이트 메인에서 `SITE_ACCESS_PASSWORD`에 설정한 비밀번호를 입력하면 열립니다. 잠금은 7일간 유지되며 상단의 **잠금** 버튼으로 다시 잠글 수 있습니다. **설정 → Google Sheets 서버 저장**에서 저장 또는 불러오기를 선택합니다. 배포 환경에서는 호스팅 서비스의 서버 환경 변수에 위 세 값을 등록한 뒤 다시 배포합니다. `.env.local`은 Git에 올리지 마세요. 사이트 비밀번호는 짧거나 다른 곳에서 쓰는 값 대신 추측하기 어려운 긴 값으로 정하세요. 기존 `GOOGLE_SYNC_PASSWORD` 환경 변수는 더 이상 사용하지 않으므로 삭제해도 됩니다.

Apps Script는 전용 **캐릭터** 탭을 만들고 캐릭터별 데이터를 저장합니다. 저장할 때 이름이 같은 캐릭터는 해당 행을 갱신하고, 새 이름은 행을 추가합니다. 불러오기는 이름이 같은 로컬 캐릭터 중 더 최근 수정본을 사용합니다. 캐릭터 시트에는 플레이어 이름도 기록할 수 있습니다. 초상화 이미지는 전송하지 않습니다. 사이트 비밀번호 확인은 HttpOnly 쿠키 세션으로 처리하며 Google Sheets API도 유효한 세션만 허용합니다. 캐릭터 수정 내용은 브라우저에 자동 저장되며 Google Sheets에는 “서버에 저장”을 눌렀을 때 기록됩니다.

Google Sheets 연결에서 **“페이지를 찾을 수 없음”** 응답이 나오면 Apps Script 프로젝트의 **배포 → 배포 관리**에서 활성 웹 앱을 열어 URL을 다시 복사하세요. `.env.local`의 `GOOGLE_APPS_SCRIPT_URL`에는 해당 웹 앱 URL 전체가 들어가야 하며 `/exec`로 끝나야 합니다. 변경 후 개발 서버를 재시작하세요. `401`과 함께 “페이지를 찾을 수 없음”이 반환되는 경우는 보통 잘못되었거나 오래된 배포 URL을 가리킵니다.

### “Google hasn’t verified this app” 경고가 보이는 경우

Apps Script가 처음 스프레드시트에 접근할 때 **스크립트 소유자**에게 Google 권한 승인을 요구할 수 있습니다. 본인이 만든 Apps Script 프로젝트를 직접 배포하면서 이 경고가 나타났고, `Code.gs`가 위 코드와 일치하는지 확인한 경우에만 경고 화면에서 **Advanced → Go to …**로 이동해 권한 내용을 확인한 뒤 승인하세요. 소유자가 아닌 계정에서 경고가 나타나거나 요청 권한이 의심스러우면 취소하세요. 공개 OAuth 앱으로 별도 Google 로그인을 구현하는 절차는 이 연동 방식에서 필요하지 않습니다.

## 규칙 데이터와 저작권

공식 룰북의 설명문, 선택지 효과, 수치, 이미지 또는 시트 디자인은 포함하지 않습니다.
데이터가 없는 규칙은 추측해 채우지 않으며, 사용자가 보유한 룰북을 참고해 직접 기록해야 합니다.
기록한 수치와 상태 변화가 공식 규칙에 맞는지는 사용자가 룰북을 확인해 주세요.
Numenera 및 관련 상표는 각 권리자의 자산이며, 이 프로젝트는 공식 제품이 아닙니다.

## 아직 구현되지 않은 기능

- 출처별 규칙 효과 원장과 타입·디스크립터·포커스 변경 시 효과 재계산
- 검증된 콘텐츠 카탈로그, 선택지 선행 조건 및 단계별 캐릭터 생성 검증
- 판정 계산·주사위 이력 및 자동 역량 소모
- 룰북에 따른 회복 굴림 계산, 사이퍼 한도·피해·방어 자동 계산
- 커스텀 규칙 데이터 편집기 및 공식 규칙 호환성 검사

성장 선택의 XP 차감과 4개 완료 후 승급은 앱에서 추적하지만, 입력한 내용이 공식 규칙에 맞는지는 판정하지 않습니다. 회복 굴림의 공식 및 판정·피해·방어·사이퍼 한도 등도 자동 계산하지 않으므로 보유한 룰북을 기준으로 적용해 주세요.
규칙 데이터 화면에 한국어판 주요 용어 대응표를 제공합니다.
